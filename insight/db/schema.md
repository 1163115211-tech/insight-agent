# 电商数据库说明（`data/ecommerce.db`）

> 归属：eval-owner。种子脚本 `insight/db/seed.py`，表结构常量 `insight/db/schema.py`。
> 评测、Web 演示、探索工具都以本文件为语义准绳；改口径请同步改这里和 `insight/eval/metrics.py`。

## 0. 基本事实

| 项 | 值 |
|---|---|
| 引擎 | SQLite 3 |
| 文件 | `data/ecommerce.db`（不入版本库，由 `python -m insight.db.seed` 生成） |
| 时间范围 | 2025-07-01 ~ 2026-09-30 |
| "上个月" | **2026-09**（评测集里的"上月"一律指这个月） |
| 评测基准日期 | 2026-10（数据只到 2026-09-30） |
| 金额单位 | 人民币元，保留 2 位小数 |
| 可复现 | `random.Random(42)`；同一版本两次生成 md5 一致 |

行数（生成后固定）：

| 表 | 行数 | 粒度 |
|---|---:|---|
| `customers` | 2,000 | 一行 = 一位注册客户 |
| `products` | 120 | 一行 = 一个 SKU |
| `campaigns` | 24 | 一行 = 一个投放计划（按季度铺满周期） |
| `orders` | 20,000 | 一行 = 一笔订单（含已取消） |
| `order_items` | 51,378 | 一行 = 订单里的一个商品行 |
| `returns` | 2,500 | 一行 = 一个退货单（挂在一条商品行上） |

## 1. 表与列

### customers（客户）

| 列 | 类型 | 语义 |
|---|---|---|
| `customer_id` | INTEGER PK | 客户 ID，1 起连续 |
| `name` | TEXT | 中文姓名（随机组合，非真实个人信息） |
| `gender` | TEXT | `男` / `女`（女约 55%，电商常见结构） |
| `age` | INTEGER | 18~65 |
| `city` | TEXT | 中文城市，30 个（上海、北京、广州……） |
| `province` | TEXT | 中文省份/直辖市，25 个（广东、江苏……） |
| `register_date` | TEXT | 注册日期 `YYYY-MM-DD`，2024-01-01 ~ 2026-09-30；**所有下单都不早于注册日** |
| `member_level` | TEXT | `普通会员` / `银卡会员` / `金卡会员` / `钻石会员` |

### products（商品）

| 列 | 类型 | 语义 |
|---|---|---|
| `product_id` | INTEGER PK | 商品 ID |
| `product_name` | TEXT | `品牌 + 品类名词 + 款式`，如 `初棉阔腿裤·经典款` |
| `category` | TEXT | 8 个品类：`女装` `数码` `家居` `美妆` `食品` `母婴` `运动` `图书` |
| `brand` | TEXT | 品牌名（每个品类 5 个品牌） |
| `price` | REAL | 标价 |
| `cost` | REAL | 成本价 = 标价 × 40%~72%，用于毛利估算 |
| `launch_date` | TEXT | 上架日期，2024-01-01 ~ 2026-06-30；**下单不早于上架日** |
| `status` | TEXT | `在售` / `下架`（120 个里 112 在售、8 下架） |

### campaigns（投放计划）

| 列 | 类型 | 语义 |
|---|---|---|
| `campaign_id` | INTEGER PK | 计划 ID |
| `campaign_name` | TEXT | 如 `2026Q3直播增长计划-23` |
| `channel` | TEXT | 投放渠道：`搜索广告` `信息流` `直播` `短视频` `私域` `联盟`（每个渠道 4 个计划） |
| `start_date` / `end_date` | TEXT | 投放起止日期，落在所在季度内 |
| `budget` | REAL | 计划预算（元） |
| `target_category` | TEXT | 目标品类，取值同 `products.category` |

### orders（订单）

| 列 | 类型 | 语义 |
|---|---|---|
| `order_id` | INTEGER PK | 订单 ID |
| `customer_id` | INTEGER FK | 下单客户；**订单日期 ≥ 客户注册日期** |
| `order_date` | TEXT | 下单日期 `YYYY-MM-DD` |
| `channel` | TEXT | **销售渠道**：`App` `小程序` `PC官网` `天猫` `京东` `抖音` |
| `status` | TEXT | `已完成` / `已取消`（约 8% 取消） |
| `total_amount` | REAL | 订单成交金额 = 该订单所有商品行 `quantity × unit_price` 之和（含已取消订单也照样算金额，但分析时通常排除取消单） |
| `campaign_id` | INTEGER FK / NULL | 归因投放计划；NULL = 自然流量。约 18% 订单可归因到当天在投的计划 |

### order_items（订单商品明细）

| 列 | 类型 | 语义 |
|---|---|---|
| `item_id` | INTEGER PK | 明细行 ID |
| `order_id` | INTEGER FK | 所属订单 |
| `product_id` | INTEGER FK | 商品；**下单日 ≥ 商品上架日** |
| `quantity` | INTEGER | 购买件数 1~3 |
| `unit_price` | REAL | 成交单价，通常等于或低于标价（大促月再低 5%） |

> 行金额就是 `quantity * unit_price`，表里不冗余存，避免和订单金额对不上。

### returns（退货）

| 列 | 类型 | 语义 |
|---|---|---|
| `return_id` | INTEGER PK | 退货单 ID |
| `order_id` | INTEGER FK | 原订单（一定存在于 `orders`） |
| `item_id` | INTEGER FK | 原订单商品行；**一条明细最多被退一次** |
| `product_id` | INTEGER FK | 商品，必须与该明细行一致 |
| `quantity` | INTEGER | 退货件数 ≤ 该明细行购买件数 |
| `refund_amount` | REAL | 退款金额 = 退货件数 × 该行成交单价 |
| `return_date` | TEXT | 退货日期，晚于下单日 1~30 天，且不晚于 2026-09-30 |
| `reason` | TEXT | `七天无理由` `尺码不合适` `质量问题` `与描述不符` `物流破损` |
| `status` | TEXT | `已完成` / `处理中` |

## 2. 业务口径（评测 gold SQL 与系统 prompt 共用）

这些定义是"同一张报表"的口径，避免同一问题两种都算对的答案：

| 指标 | 定义 |
|---|---|
| **GMV（成交总额）** | `orders.status = '已完成'` 的订单，`SUM(orders.total_amount)`；不扣退货 |
| **净销售额** | GMV − 已完成退货的 `refund_amount` 合计 |
| **订单数** | 默认指 `status='已完成'` 的订单笔数；题目未特别说明时都排除取消单 |
| **销量** | `SUM(order_items.quantity)`，统计口径跟随订单状态 |
| **客单价（AOV）** | GMV ÷ 已完成订单数（订单级指标；按客户/品类/城市分组时，分母仍是该组的已完成订单数，不是客户数） |
| **客单件数** | 商品件数合计 ÷ 已完成订单数 |
| **退货率（订单口径）** | 有退货记录的已完成订单数 ÷ 已完成订单数。注意：仅 2026-08-31 前的订单可能产生退货，跨期比较时口径一致即可 |
| **退货率（金额口径）** | `SUM(returns.refund_amount)` ÷ GMV（同一时间窗） |
| **退货率（商品口径）** | 退货件数 ÷ 销售件数（同一时间窗、同一商品/品类） |
| **同比** | 本期 ÷ 去年同期 − 1；"上月同比" = 2026-09 vs 2025-09 |
| **环比** | 本期 ÷ 上一期 − 1；"上月环比" = 2026-09 vs 2026-08 |
| **投放 ROI** | 归因订单的 GMV ÷ 计划预算 |
| **新客 / 老客** | 以该客户全周期**首笔已完成订单日期**判断：首单落在统计期 = 新客，否则老客（首单被取消不算"首笔购买"） |
| **在售商品** | `products.status = '在售'` |

口径补充：
- 退货单**不区分处理状态**：分析退货率/退款金额时默认 `已完成` + `处理中` 都计入（钱已经退或正在退）。
- "客单价"在任何分组下都是订单级指标（分母是订单数）；如果要按客户算，题目会写"人均消费金额"。

统计期过滤建议：日期是 TEXT，用 `order_date LIKE '2026-09%'` 或 `substr(order_date, 1, 7) = '2026-09'`；
跨月/跨年请显式写月份，不要依赖 SQLite 的 `date('now')`（评测数据是固定历史区间，机器当前时间无关）。

## 3. 数据里的"业务故事"（用来判断分析结果合不合理）

生成时刻意埋了这些结构，读图/写结论时应该能看到：

- **季节性**：2025-11（双 11）、2026-06（618）是明显高峰；2026-02 春节回落。
- **渠道结构变化**：抖音、小程序占比上升，PC 官网明显下滑（所以渠道 GMV 同比会分化）。
- **客户长尾**：少数客户订单数远高于平均（复购集中），Top 10 客户贡献可观但不会超过整体 10%。
- **品类结构**：数码 GMV 最高但销量少（单价高）；美妆/女装/图书件数多、客单低。
- **毛利**：`cost` 约为标价 40%~72%，可做毛利率分析（未出现在 52 题里，但可自由发挥）。
- **退货**：七天无理由占四成，大促后（2025-12、2026-07）退货量偏高；退货只发生在 2026-08-31 前完成的订单上。

## 4. 已知边界（评测题不要踩）

1. `returns` 不覆盖 2026-09 下单的订单 → 不要出"9 月下单的退货率"这类题（会得到 0 或极小值）。
2. 2025-04 ~ 2025-06 没有数据 → 不要出 2026-04~06 的同比题（去年同期为空）。
3. `orders.status` 只有两种值；不存在"待付款""退款中"等中间态。
4. 归因订单只覆盖投放期内的计划，无归因的订单 `campaign_id IS NULL` 属于自然流量。
5. 商品可能下架，但历史订单仍保留；按商品维度统计时无需过滤 `status`。
