## 一、项目条目（推荐 4 条，按这个顺序）

**问数 Insight Agent — 自然语言数据分析 Agent**（个人项目 · 2026.09–2026.10）

- 基于 **LangGraph** 设计 10 节点状态机（意图分诊 → schema 探查 → 计划 → SQL 生成 → 校验 → 执行 → 自修复 → 可视化 → 结论），实现自然语言到数据分析结果的端到端链路；单题 P50 延迟 7.4 秒、约 5,000 tokens、<b>¥0.015</b>
- 设计 **三层只读沙箱**（词法级静态校验 + SQLite 只读连接 + 执行超时/行数熔断），拦截 DDL/DML、多语句与非白名单表，模型生成的 SQL **无执行权限**
- 实现 **错误回灌自修复**：将数据库原始报错注入重试 prompt，最多 3 次，配合 `attempts` 状态计数与图递归上限双保险；并以假 LLM 注入报错的离线用例验证修复闭环
- 自建 **52 题评测集**（单表/多表/时间序列/窗口函数/比率/综合），以**执行准确率**为主指标做 A/B 对照：完整状态机 **84.6%** vs 一次性生成基线 59.6%，**+25.0 pp**

## 四、面试官最可能追问的三个点（提前准备）

| 追问 | 你的答案落点 |
|---|---|
| 「提升 25.0pp 怎么来的？可信吗？」 | 同模型同库只改链路；提升来自自修复 + 先计划再写；给出按难度/tag 的分布，承认数据集自建、有局限 |
| 「安全怎么保证的？」 | 三层沙箱，重点是**执行权不在模型手里**；讲 `'delete me'` 字符串误杀那个坑 |
| 「为什么用图？循环不行吗？」 | 中断/恢复/可观测三个真实需求；主动说"简单任务不该上图" |

## 五、三个「不要」

1. **不要写**「熟悉 LangChain/LangGraph 源码」——除非你真读过；会被追问版本差异
2. **不要写**「准确率 95%」——自建评测集的高分反而可疑，写清楚口径和数据集规模
3. **不要罗列**十个框架名——面试官只关心你解决过什么具体问题
